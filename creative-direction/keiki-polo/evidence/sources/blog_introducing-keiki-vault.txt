Keiki Vault: Face ID approvals for any tool your agent runs
Keiki Vault puts a Face ID approval card in the iMessage thread before your agent sends an email, pays an invoice or runs any risky tool. Here's who it's for, how to set it up and the SDK code.
Your agent is about to send an email as you. Or pay an invoice, or cancel a booking. In most agents, the safety check is a text that says "reply YES to confirm", and anyone holding the phone, or any message that looks like a yes, can approve it.
Watch the demonstration
Keiki Vault puts a Face ID button on every risky action your agent takes on iMessage.
 The approval card opens in the thread and shows exactly what will happen. The person taps Approve, looks at their phone, and the action runs. A typed "yes" can't approve it.
Why this matters
An agent that can act needs a way to ask first. Asking in words works for low-stakes actions, but words are easy to fake. A forwarded message, a prompt injection in an email or a friend borrowing the phone can all produce a "yes".
Vault replaces the typed yes with a signed one:
Face ID, every time.
 Approve and Decline are both protected by Face ID. Each decision is signed with a key kept on the device and checked by Keiki before anything runs.
The card shows what will run.
 Your tool describes the action as a card: the email with its recipient and subject, the refund with its amount, the invoice with its total. Keiki adds a footer naming the tool, so the person always knows what they're approving.
The card updates in place.
 After the tap, the same bubble changes to 
Approved
, 
Declined
 or 
Didn't go through
. There's no second message to read.
A new phone has to prove itself.
 The first approval from a contact enrolls their device key. If a different key shows up later, Keiki asks for a six-digit code that the contact sends from their own number before that key can decide.
It works for any tool you build.
 Vault isn't a fixed list of actions. If a tool asks for approval, Vault can draw its card.
Who can use it
Vault is for teams whose agents act for people on iMessage: personal assistants that send email and pay bills, support agents that issue refunds, and booking agents that change reservations.
To use it, you need:
A dedicated Keiki iMessage line.
 Cards are sent only from a dedicated iMessage line bought through Keiki. Imported, shared and pool lines don't send cards.
A 1:1 conversation.
 Cards aren't sent in group chats or on other channels.
Keiki Vault on the contact's iPhone.
 Each person installs it once from the App Store.
Approval cards don't need any add-on. Presentation cards, which show your own web page inside the thread, need the Dynamic UI add-on.
How to get started
Give your agent a dedicated iMessage line from the Keiki dashboard.
Mark the tools that need a person's yes with 
approval: 'ask'
.
Add 
approvalProof: 'verified'
 so only a Face ID decision can approve them.
Optionally, describe each action as a 
card
, so people see an email or a receipt instead of raw arguments.
Text your agent from your iPhone with Keiki Vault installed, and ask it to do something that needs approval.

Webhook tools
Tools you register over the API take the same policy. For a webhook tool, 
preflight: true
 makes Keiki send the call once with 
context.preflight: true
 before asking, so your server can reject a bad call before anyone sees a card. When an approved call runs, 
context.approval
