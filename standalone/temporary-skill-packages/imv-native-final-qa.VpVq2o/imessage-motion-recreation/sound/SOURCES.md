## Media roles in the base library

FFprobe 7.1.5 found 30 silent H.264 masters under `resources/silent-picture-masters-v1/`, six original source films with AAC, and 30 historical H.264/AAC deliverables. The independent UI-only and combined preview sets each hold six H.264/AAC files. The stream inventory identifies what can be decoded. The sidecars and source manifests identify whose audio it is.

- Poke's GSAP silent master has 1,283 frames at `30000/1001` fps and lasts 42.809433 seconds. Its SHA-256 is `61286445805216b985028595c7e3f0f8dd01c2da44695b658a867145eef0d772`. The historical project deliverable's sidecar documents that its AAC came from the supplied reference. The curated Poke source and the repository's original reference also have AAC. [Historical mux sidecar](../../../projects/04-poke-complete-v1/imessage-recreations/deliverables/04-poke/gsap.audio.json)
- The Poke `04-poke-ui.mp4` preview contains a boosted independent UI-only score. `04-poke-recreated.mp4` adds a separate music stem. Their sidecars pin the same picture hash and record `reference_audio_reused: false`. The paired `ui.flac` and `music.flac` are editable stems. The `full_mix.flac` file is a historical combined master. [Poke UI preview record](../../../resources/complete-ui-audio-source-v1/imessage-recreations/audio-recreation/ui-previews/04-poke-ui.json) · [Poke combined preview record](../../../resources/complete-ui-audio-source-v1/imessage-recreations/audio-recreation/ui-previews/04-poke-recreated.json)
- Kenney's Interface Sounds and unicaegames' Keyboard Soundpack 1 are independent CC0 recordings prepared in the base library. Keep their source records, hashes and notices with any extracted elements. The synthesis bank also contains project-authored procedural one-shots. Keep those credited to the project, with the exact revision and recipe or WAV hash. [Library license evidence](../../../resources/complete-ui-audio-source-v1/imessage-recreations/audio-recreation/library/LICENSES.md) · [Kenney](https://kenney.nl/assets/interface-sounds) · [unicaegames](https://opengameart.org/content/keyboard-soundpack-1-typing-and-single-keystrokes)

A local probe command for new media:

```sh
ffprobe -v error -show_entries stream=index,codec_type,codec_name,start_time,duration,avg_frame_rate,nb_frames -of json "$FILE"
```

## Reference measurement

**Historical checker control.** Rerun the `69595df` sound trial against the SHA-pinned `b303dde` `final-picture.mp4`. Duplicate `sound-trial/pinch/final.json` beside the original, set `coach-send`'s `impact_delta_ms` to `200`, and build the duplicate. The same shifted AAC export passed the old checker against its regenerated `qc.json` with correlation 1.000 and residual 0.0 ms. It failed against the baseline `qc.json`. The measured sample start was 7.290 s and the baseline expected start was 7.090 s. Both checks saw the same picture bytes and timestamps. This makes a regression case for an expectation derived from decoded picture. [Historical build and check commands](https://github.com/tecxbro/imessagevideo/blob/69595dfa2ef588a59d1b0b4d5836817a49d0f809/sound-trial/README.md)

In a contact sheet of every fourth AffordiHome frame from 216 to 288, the phone is lit at f220, dark from f224, relit at f272, and the first sampled large notification appears at f276. The daylight change carries the waiting interval. Decoded stereo RMS is −17.90 dBFS over 7.467–8.133 s, −22.20 dBFS over 8.9–9.2 s, and −11.56 dBFS over 9.2–9.55 s. The measured rise accompanies the return of the notification. An original score can try a quiet hold and one defined payoff against an alternate with an uninterrupted bed. The source is a finished mix, so the measurement does not identify separate effects or musical elements. Human listening is pending. ## Production references beyond the six checkouts

- FFprobe exposes decoded frame timestamps and packet timestamps separately. Read the frame in presentation order and check the audio track's own clock after muxing. For a variable-rate clip with a nominal frame-rate field, use presentation timestamps to map the observed frame to the cue time. An MP4 AAC track can contain encoder priming and remainder samples. Decode with the container's presentation edit applied and measure on that clock. [FFprobe](https://ffmpeg.org/ffprobe.html) · [AAC priming and edit lists](https://developer.apple.com/documentation/quicktime-file-format/appendix_g_audio_priming_handling_encoder_delay_in_aac)
- ITU-R BS.1770 defines programme loudness and true peak separately. Use `ebur128=peak=true` to measure the encoded export and establish any delivery ceiling alongside the actual brief. Measure designated quiet and active spans separately from integrated loudness. `silencedetect` reports intervals under an explicit threshold and minimum duration. A time-stamp discontinuity calls for a separate stream check. [ITU-R BS.1770-5](https://www.itu.int/rec/R-REC-BS.1770-5-202311-I) · [FFmpeg filters](https://ffmpeg.org/ffmpeg-filters.html)
- Apple's feedback guidance pairs audio with visible state changes and calibrates the interruption to the information. In the film, a confirmation sound can reinforce the decision while the visible control still supplies the proof on muted playback. [Apple feedback guidance](https://developer.apple.com/design/human-interface-guidelines/feedback/)
