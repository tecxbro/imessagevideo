# Linq late sequence refinement

1. Ran an every-frame native scan over all 1,458 frames of the frozen v9 GSAP export. Mean MAE was 14.478, with multiple large peaks between the previously checked held states.
2. Compared the twenty separated peaks at native size. The first large errors included placeholder Games artwork, overlapping chess states and mistimed camera/phase boundaries. Later errors included a frozen Four in a Row board, missing overlap during horizontal app transitions, premature boarding-pass entry and a guessed gallery zoom.
3. Split work by stable root IDs. The original Linq/Rene builder owns the rest of the Linq timeline. This branch owns `rich-group-10` (Four in a Row), `g-942` (boarding pass) and `broad-v5-group-72` (phone gallery). It will provide an ID-scoped helper so independently corrected sections can merge.
4. Rejected an immediate boundary-rounding fix: native source frame 941 contains two overlapping apps moving horizontally, rather than a hard cut. A one-frame lifecycle snap alone would conceal the actual motion error.
5. Extracted exact source frames around the Four in a Row entrance, held game states and exit, plus boarding/gallery frames. Generated a batch of actual GSAP boarding checkpoints from frozen v9 to distinguish design errors from entrance/camera errors before choosing a correction.
6. Rebuilt the Four in a Row panel from its static original UI with counters removed, then measured its native silhouette and eleven independent counter tracks. Initial threshold geometry was 2–4 px off because compression changed the detected edge. A small static-header alignment search and actual per-counter ellipse bounds reduced native MAE at frames 965/980/995 to 1.150/0.979/0.792 (previous 42.191/48.197/113.738). The remaining frame-941 error is the separately owned outgoing chess panel, not the incoming game.
7. The first broad Powell camera fit jumped into a wrong scale basin during the rapid gallery zoom. Preserved that rejected fit, added coarse global seeds and bounded local refinement, then checked actual source anchors. This found camera scales about 3.90 at 40.0 s, 3.70 at 40.167, 3.04 at 40.333, 1.77 at 40.5 and 1.0 by 41 s. Also diagnosed an inconsistent downsampling filter in the measurement fixture and matched sampling before using its losses.
8. Source gallery motion also moves columns independently. Fitted the left and right column offsets separately after the shared camera. Found baseline placement errors in two cropped partial-phone assets; preserved their drift slopes while correcting their reference positions.
9. Took ownership of the single Games placeholder group. Exact frames show that the six tile interiors themselves animate, so one static screenshot would still be inaccurate. Extracted independently bounded per-tile artwork poses, preserving editable geometry, native held label outlines, a separate icon and handle. No complete source frame is a runtime layer.
10. A connected-color-component detector failed on Word Games because its preview is split into disconnected colored blocks. Diagnosed that segmentation assumption before retrying. Switched to a saturated-pixel union inside each tile's narrow expected region, using the first teal tile to determine common vertical motion so neighboring rows cannot contaminate the measurement.
11. A checkpoint timestamp rounded below `frame / fps` selected the prior game-preview pose. Added `--frames INDEX,INDEX` to the batch checkpoint renderer so exact native frame times are computed internally. After this correction, Games frames 136 and 145 measured MAE 1.723 and 1.221; the placeholder baseline at 136 was 64.727.
12. Measured the boarding pass's actual top origin from a frame where both its top and inner white card were visible. The true top is -234 in the 40 s resting coordinate system; an initial arbitrary -300 origin put the header text 66 px too low during entry. Kept the background, UI content translation and camera independently editable.
13. Traced the actual white destination text/aircraft silhouette and black/gray passenger fields instead of retaining approximate font weights. The source's white title coordinates also shift about three pixels during entry, so measured that small content offset separately from the card background.
14. The boarding background varies horizontally as well as vertically. A single linear gradient could not match it. Reconstructed only its smooth color field from masked, robust polynomial fits, storing coefficients and fit error. Generated textures contain no reference UI, labels or complete frame pixels; native foreground geometry stays separate.
15. Fitted the common gallery zoom at every native frame from 1200 to 1226 and independent column drift after the camera. The original bounded central phone artwork is byte-identical to the source crop at frame 1245; used that proven pose to reject a neighboring optimizer minimum.
16. Identified cropped edge artwork by its actual source capture time, rather than assuming every crop came from the same frame. The lower center partial phone follows the central phone by 601 px; the upper right partial follows the right phone by -76 px. Extended the left chat phone with measured missing lower artwork while preserving its original held pixels.
17. Tracked all three phone columns at native frames 1227–1271 and measured the gallery's actual opacity from an isolated upper-right phone ROI. The source holds near full opacity until frame 1265, then fades through 1266–1270 and disappears at 1271. Earlier two-anchor interpolation had faded it too soon and cut it off while still visible.
18. Accepted the four-ID branch with native checkpoint evidence and frozen patch hashes in `root-late-release.json`. All 1,258 frames outside the declared intervals produced byte-identical SVG against v9. The missing check-in bubble at 39.5 belongs to the original builder's separate `g-925` lifetime fix. No full render was launched from this branch; the builder will merge independently corrected sections before encoding and scanning the combined timeline.
