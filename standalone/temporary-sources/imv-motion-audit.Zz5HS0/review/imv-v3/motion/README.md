# Motion review

The [catalog](../../../skill/imessage-motion-recreation/motion/catalog.json) maps each of 77 entries to exact silent MP4 bytes, a SHA-256, a render command and a frame-addressed event map. The 77 include 75 distinct motions, one grouped send/reply demonstration and one sheet variant. The source study contains seven observed-only movements. Six different entries were reused independently in a new scene. See [reuse evidence](reuse/index.json) and [the build room](https://github.com/tecxbro/imessagevideo/issues/7).

- **Default clips.** Pillow and FFmpeg at 720×480, 30 fps, 72 frames. Every export was fully decoded and the scene passed Observer's timeline resolver. The frame sheets sample the stored default exports.
- **Other renderers.** [Per-entry evidence](samples/renderer-samples.json) records the number of distinct decoded images from each nine-frame accelerated script pass through HTML/SVG, GSAP, Remotion and native Motion Canvas. The probe keeps the original tracks, layers, paths and media and retimes each recipe to nine frames. Each method decoded all 693 probe frames. Across the first 73 entries, the highest per-entry mean RGB channel error against Pillow was 1.88 on a 0–255 scale in the 180×120 sampled frames. [Cross-renderer measurements](samples/renderer-pillow-rgb-delta.json) Check consecutive frames at the final cadence when matching an edit or assigning a cue.
- **Conversation adapter.** The [UI previews](ui/) come through the team's `ui.adapter` at `5e2ff5a`. All 13 complete exports decoded through Pillow and their timelines resolved. The adapter delivers its own styling, timing and layer placement. The corresponding default preview retains the individual recipe's described choreography.
- **Independent reuse.** [Tidal Archive](reuse/tidal-archive/decoded-comparison.png) packages a cold run at `de04deb`, changed artwork, replacement content and decoded metrics. [Field Guide](reuse/field-guide/field-guide-motion.png) packages an independent changed-art rail. In both cases the moving layer changed without displacing the fixed one. Recreation's changed-art run and Direction's changed-copy run are recorded in the build room. The [Orchard Crew reuse](reuse/orchard/orchard-ui-onset.png) enters a changed remote reply on f35 through the conversation adapter. Old rows rise while the heading and composer hold. Direction also reran the previously missed brief with replacement copy and a visitor-pass label, verifying the original four edit landmarks. The [North Quay test](reuse/north-quay/README.md) used the original volunteer brief through the shared CLI. The reuse count is unique entry IDs.
- **Sound and edit.** Sound independently confirmed send f32 / sample 51200 and receive f51 / sample 81600 in the early cut. Motion ran Sound's crop-template resolver against that same clip and independently resolved the send at f32. The two IDs survive the chronological layout correction. Observer's combination test now resolves `beat-2.cut` f72 with `uiState: null`. Heading events f92 and f123 inherit that state. ## Misses and revisions

The early selector sometimes guessed the wrong moving layer from phrases such as “leave the exhibit title where it is.” It now binds the moving and fixed clauses, handles negation, and adapts a supported axis explicitly. A later blind check also found ambiguous wording around the stationary typing field, an inbound reply making room, pinned thumbnails and a reading pause. Those phrases now have role-based regression checks. Direction’s first screen-to-tin brief initially returned `missing`. The locked source established the independent phone, focus and continuation-camera tracks used in [the editable entry](screen-to-physical-prop.mp4). The full-exit option and closed-prop hold are authored for the brief. The source-style option keeps the handset edge until the cut. The [replaced-prop example](samples/replaced-prop/prop.mp4) passes a new transparent image via the content file and carries the same object across the cut.

A vertical photo rail, a third swipe from the same attachment stack, and a true 3D page curl return `missing` with a specific reason. Album turning in the catalog uses a projected flat hinge. Video scrubbing uses ordered still samples. The adapter's horizontal paging uses one adjacent photo per swipe. A native multi-photo send followed by inline paging under a fixed conversation header still lacks the requested continuous Dataset capture, so the short loop remains an authored adapter demonstration. The source inventory records the native observations already on hand. Human picture review remains pending.

The four added recipes use fixed value counting, resolving glyphs, parting picture planes and fanning pinned swatches. Each has a full 72-frame Pillow preview and moving nine-frame probes in each of the other four engines.

The [v3.2 retest](v3.2/README.md) contains both selector regressions, a decoded counter hold with supplied endpoints, and a portable photo comparison with changed content and event maps.
